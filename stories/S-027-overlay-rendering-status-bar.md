# S-027: Overlay Rendering + Diff Preview + Status Bar

## Narrative

As a daemon operator, I want the permission overlay to display the pending prompt's
tool details (including a unified diff for Edit operations), present Accept/AcceptAlways/Reject
keyboard hints, and show a status bar with mode indicator and drop counter, so that I
have all the information I need to make permission decisions at a glance.

## Acceptance Criteria

### AC-001 (traces to BC-2.06.010 postcondition PC-1 — overlay widget layout)
When `AppMode::Overlay { stack, .. }` is active, `monocle-tui` renders a centered modal
over a dimmed background. The modal displays:
- Header: `"Permission Request"` with the `session_id` and `tool_name`
- Body: tool-specific content (see AC-003 through AC-006)
- Footer: keyboard hint line: `"[y] Accept  [A] Accept Always  [n/r] Reject  [Esc] No-op"`
The modal width is capped at `min(terminal_width - 4, 100)` columns. The overlay stack
depth is shown as `"(1 of N)"` in the header when `N > 1`.

### AC-002 (traces to BC-2.06.010 postcondition PC-2 — dimmed background)
The content behind the overlay modal is rendered with a `Modifier::DIM` style applied
to all non-modal cells. The sessions panel and event ribbon remain visible but dimmed
to indicate they are inactive.

### AC-003 (traces to BC-2.06.017 postcondition PC-1 — Bash tool display)
For `ToolPayload::Bash { command }`: the modal body renders the command in a bordered
`Block` with title `"Command"`. If the command exceeds the modal height minus 6 rows,
it is truncated with `"... (truncated)"` at the end.

### AC-004 (traces to BC-2.06.017 postcondition PC-2 — Read tool display)
For `ToolPayload::Read { path }`: the modal body renders the path in a single-line
`Block` with title `"File"`. No truncation is needed.

### AC-005 (traces to BC-2.06.015 postcondition PC-1 — Edit diff preview via similar)
For `ToolPayload::Edit { old_content, new_content, path }`: the modal body renders
a unified diff generated by `similar::TextDiff::from_lines(old_content, new_content)`.
The diff is rendered line-by-line with:
- Added lines (`+`) in green (`Color::Green`)
- Removed lines (`-`) in red (`Color::Red`)
- Context lines in default color
The path is shown in the modal header: `"Edit: <path>"`.

### AC-006 (traces to BC-2.06.017 postcondition PC-3 — Generic tool display)
For `ToolPayload::Generic { tool_name, tool_input }`: the modal body renders
`serde_json::to_string_pretty(tool_input)` in a `Block` titled `"Tool Input"`.
If the JSON exceeds the modal height minus 6 rows, scroll hints are shown:
`"↑↓ to scroll"` in the footer alongside the decision keys.

### AC-007 (traces to BC-2.06.015 invariant INV-1 — similar in monocle-tui only)
`similar` crate is imported ONLY in `monocle-tui`. The diff generation code MUST NOT
appear in `monocle-core`. If a refactor is proposed that moves diff logic to
`monocle-core`, it is a purity boundary violation and MUST be rejected.

### AC-008 (traces to BC-2.06.019 postcondition PC-1 — status bar always visible)
The status bar is rendered as the last row of the terminal at all times (including when
the overlay modal is shown). It is NOT dimmed by the overlay background dimming. The
status bar shows:
- Left: current `AppMode` indicator: `"[DASHBOARD]"`, `"[FILTERING]"`, `"[OVERLAY N]"`
  (where N is the overlay stack depth), or `"[FULLSCREEN]"`
- Right: `"[dropped: N]"` in yellow when `drop_counter > 0`, otherwise nothing

### AC-009 (traces to BC-2.06.020 postcondition PC-1 — overlay timer display)
For each active `PromptModal`, the time elapsed since `received_at` is displayed in the
overlay footer next to the stack depth: `"Waiting: <Ns>"` where N is
`Instant::now().duration_since(received_at).as_secs()`. The timer updates on each
terminal render tick (100ms tick rate).

### AC-010 (traces to BC-2.06.021 postcondition PC-1 — received_at ordering in overlay)
When `stack.len() > 1`, prompts are displayed in FIFO order (oldest first, per AC-002
of S-026). The `"(1 of N)"` indicator always refers to the oldest pending prompt being
the active decision target.

### AC-011 (traces to BC-2.06.010 invariant INV-1 — no blocking render)
All diff generation (via `similar`) and JSON pretty-printing (via `serde_json`) MUST
complete within a single render frame (target: < 5ms for typical inputs). These are
CPU-bound operations on strings — they do not block the async runtime. No
`tokio::spawn` or background threading for render computations.

## Previous Story Intelligence

S-026 (permission overlay core): `App.overlay_stack: VecDeque<PromptModal>` contains
the prompts to render. `App.mode: AppMode` determines whether overlay rendering is
active. The `PromptModal.received_at: Instant` is set when the TUI receives the
`PermissionPromptQueued` message.

S-025 (TUI skeleton): ratatui layout uses `Layout::default().direction(Direction::Vertical)`
with constraints for panels and status bar. The overlay widget is a `Clear` + `Block`
overlay rendered on top of the existing layout. The status bar occupies the last
`Constraint::Length(1)` row.

`similar` 3.x API: `TextDiff::from_lines(old: &str, new: &str)` returns a `TextDiff`
that yields `Change` items. Each `Change` has a `tag()` method returning
`ChangeTag::Insert`, `Delete`, or `Equal`. Iterate via `.iter_all_changes()`.

## Architecture Compliance Rules

From `architecture/SS-tui-core.md`:
- `similar` lives in `monocle-tui` ONLY — never `monocle-core` (purity boundary)
- Status bar is NOT dimmed by overlay background — it remains full-brightness at all times
- Render loop tick rate: 100ms (for timer updates)
- Modal width: `min(terminal_width - 4, 100)` — enforced in render, not hardcoded
- `similar::TextDiff::from_lines()` for Edit diffs — NOT a custom diff implementation
- `serde_json::to_string_pretty()` for Generic payloads — NOT manual JSON formatting
- All render operations are synchronous and complete within one frame (< 5ms target)

**Forbidden Dependencies:**
- `similar` in `monocle-core` — purity boundary violation
- Custom diff algorithm — use `similar 3.x` exclusively
- Background threads for render computation — all rendering is synchronous
