## Build/Release Surface

### `.github/workflows/release.yml`

Single workflow on tag push `v*`:
- ubuntu-latest, Go 1.25
- `goreleaser-action@v6` with `args: release --clean`
- Uses `GITHUB_TOKEN` (default permissions: `contents: write`).
- No code-signing step.
- No SBOM generation.
- No `cosign` / Sigstore.

### `.goreleaser.yml`

- Build matrix: darwin/linux × amd64/arm64.
- Build flags `-s -w` (strip + omit debug info).
- Archives: tar.gz, named `lazyclaude_{Version}_{Os}_{Arch}.tar.gz`.
- Checksums: `checksums.txt` produced (sha256 by default).
- Changelog excludes commits starting with `docs:`, `chore:`, `test:`.

### `install.sh`

`curl | sh`-style installer:
- Reads `GET /repos/any-context/lazyclaude/releases/latest` via `curl` to get tag.
- Downloads `lazyclaude_<ver>_<os>_<arch>.tar.gz` from the GitHub releases URL.
- Extracts to a tmpdir and installs to `${LAZYCLAUDE_INSTALL_DIR:-$HOME/.local/bin}/lazyclaude` mode 0755.
- **Security note:** no checksum verification in the install script. The `checksums.txt` is generated by goreleaser but the installer doesn't fetch and verify it. This is consistent with most ecosystem `curl | sh` installers but worth flagging.
- No GPG signature verification.
- Uses `set -e` for fail-fast.

## Authn / Authz Surface

### MCP Server Token (`internal/server`)

| Property | Value |
|---|---|
| Source | `crypto/rand` 16 bytes hex-encoded (`generateToken` referenced root.go:408; daemon.GenerateDaemonToken uses same shape — daemon/server.go:778-784) |
| Storage | `~/.claude/ide/<port>.lock` JSON with `authToken` field; mode unspecified by Go default (typically 0644 — verify in deep pass) |
| Header(s) accepted | `X-Claude-Code-Ide-Authorization` (preferred) or `X-Auth-Token` (curl-test fallback) — server.go:355-363 |
| Comparison | `subtle.ConstantTimeCompare` — server.go:278 |
| Token rotation | Every server restart generates a new token; hooks rediscover via lock-file scan. No long-lived rotation. |
| URL-query auth | **EXPLICITLY REJECTED** to avoid log leakage — server.go:276 (comment). |

### Daemon Token (`internal/daemon`)

| Property | Value |
|---|---|
| Source | `daemon.GenerateDaemonToken()` = `crypto/rand` 16 bytes hex |
| Storage | `<runtimeDir>/daemon.json` mode 0600 (daemon/server.go:766) AND emitted to stdout (daemon_cmd.go:102) |

| Comparison | `subtle.ConstantTimeCompare` (daemon/server.go:190) |

| Token rotation | Per daemon restart. RemoteConnection caches token in-memory; on reconnect, must re-bootstrap via SSH. |

### Hook → MCP

Hooks are subprocesses of `claude` (which is a subprocess of tmux). They:
1. Read `~/.claude/ide/*.lock` (mode depends on `claude` writer; typically 0644 — readable by user).
2. Probe PID liveness via `process.kill(pid, 0)` (does not actually send a signal but tests permission).
3. POST to `127.0.0.1:<port>/notify` with the token in `X-Claude-Code-Ide-Authorization`.
4. Time out (300ms PreToolUse / 2000ms Notification) via `req.on('timeout', () => req.destroy())`.

## Network Surface

### Local-only listeners

All HTTP/WebSocket listeners bind to `127.0.0.1` only:
- `internal/server/server.go:124`: `net.Listen("tcp", "127.0.0.1:0")`
- `internal/daemon/server.go:139`: same
- `internal/daemon/tunnel.go:123`: tunnel poll target `127.0.0.1:<localPort>`

WebSocket origin check: `OriginPatterns: []string{"localhost:*", "127.0.0.1:*"}` (server.go:284). Only localhost origins accepted.

### Outbound network

- `ssh` and `scp` subprocess calls (daemon/ssh.go, daemon/tunnel.go).
- `node` subprocess from hooks (HTTP POST to 127.0.0.1 inside the same machine).
- `install.sh` makes outbound HTTPS calls to `api.github.com` and `github.com/.../releases/download/`.
- `make readme-gif` / `make test-vhs` requires Docker.

### Reverse tunnel

`ssh -L <local>:127.0.0.1:<remote>` is the only forwarding mode used. **No `-R` reverse tunnels.** Mirror windows route through the locally-bound tunnel port to reach the remote daemon. (Previously, README and dev archive mention Unix-domain socket forwarding, but daemon/remote_provider.go:81-82 explicitly states: "Socket tunnel forwarding was removed because remote sshd environments often block Unix domain socket forwarding.")

## Filesystem & Path-Handling Risks

### File mode discipline

| File | Mode | Source |
|---|---|---|
| `<runtimeDir>` (e.g. `/tmp/lazyclaude/`) | 0755 | root.go:52 |
| `daemon.json` | 0600 | daemon/server.go:766 |
| `hooks-settings.json` | 0600 | core/config/hooks.go:71 |
| `state.json` (session store) | 0644 default (verify in store.go) | Pass B deepening needed |
| `askpass-*.sock` | 0600 | askpass.go:67-68 |
| `askpass-*.sh` | 0700 | askpass.go:88-89 |
| Daemon runtime dir | 0700 | daemon/server.go:758 |

**Inconsistency:** root.go:52 creates `/tmp/lazyclaude/` as 0755 (world-readable). Daemon's runtime dir is 0700. The MCP server log lives at `/tmp/lazyclaude/server.log` (root.go:416) — readable by everyone on the system.

### Absolute path enforcement

- `handler.go:139-146` (`validateFilePath`) requires absolute paths for openDiff `old_file_path`.
- `session/manager.go:256-259` does `filepath.Abs(dirPath)` for session paths.
- `server.go:533-537` resolves relative Edit `file_path` against `cwd` before reading.

### Path-traversal risk

- `state.json` stores session paths verbatim. If a malicious state.json names `../../etc/passwd`, GUI display would show the literal string. Operations are based on the tmux window (not the displayed path), so no actual file read happens.
- Worktree creation uses `WorktreePath(projectRoot, name)` and `ValidateWorktreeName(name)` rejects invalid names (session/manager.go:316). The validation logic is in session/worktree.go (deep pass).

### Symlink handling

Not explicitly hardened. Edit's 2 MB cap is on regular files only (`fi.Mode().IsRegular()` — server.go:541), which inherently rejects symlinks. Otherwise, plain `os.ReadFile` and `os.Stat` are used.

## Command Injection Surface

### `ssh`, `scp`, `tmux`

#### tmux control mode (`internal/core/tmux/control.go`)

- `validateControlTarget` rejects `\n \r ;` and spaces in target args (control.go:188-198).
- `validateControlKey` rejects `\n \r ;` in key args (spaces allowed for space key) (control.go:200-209).
- `SendKeysLiteral` rejects newline, carriage return, NUL in the literal text (control.go:163-169) and escapes backslash + double-quote (control.go:182-185).
- **Risk:** The escaping is "may need review for edge cases with tmux control mode quoting (e.g., unusual Unicode, combining characters, or tmux version-specific behavior)" — an explicit TODO comment at control.go:176-179. **P1 risk for monocle.**

#### tmux exec adapter (`internal/core/tmux/exec.go`)

- Uses `exec.Command("tmux", args...)` — argument-array form, so shell escaping is not a vector.
- Targets and keys passed to `SendKeysLiteral` are passed as separate args.

#### SSH command construction

- `ExecSSHExecutor.Run` uses `exec.CommandContext(ctx, "ssh", args...)` argument-array form (daemon/ssh.go:60). No shell.
- **However**, the remote command is a single string argument: `args = append(args, sshHost, command)`. SSH passes that string to the remote shell. The remote shell expansion happens server-side.
- Remote commands are base64-encoded before being placed in the SSH string (daemon/remote_provider.go:434-435): `eval "$(echo <base64> | base64 -d)"`. **This prevents local shell expansion** of the command in the SSH arg.
- `shell.Quote` is available for cases where base64 isn't appropriate (e.g. `buildTmuxAttachCommand` quotes the window name — daemon/remote_provider.go:461).
- **Risk:** the buildTmuxAttachCommand path uses `shell.Quote` inside an SSH command string. The .claude/CLAUDE.md explicitly warns: "No nested quoting. Do not use `shell.Quote` inside SSH command strings." But the code at remote_provider.go:451-462 DOES use shell.Quote inside the tmux command which is then placed in an SSH arg. This may be the warned-against pattern — needs scrutiny in Pass B.
